# Task brief and scenario routing

Use the smallest narrative that performs the communication job. An agenda is not a narrative.

## Shared brief

| Field | Decision it controls |
|---|---|
| Speaker | authority, tone, and what can be promised |
| Audience | prior knowledge, objections, and decision power |
| Job | educate, persuade, recommend, sell, facilitate, or obtain approval |
| Expected action | what the closing slide must ask for |
| Evidence | which claims are facts and what remains unknown |
| Duration | number and density of slides |
| Delivery context | live talk, async read, class, boardroom, or sales meeting |

## Product proposal

Use when asking for prioritization, project approval, or validation resources.

Suggested arc: why now → user/problem evidence → limits of the current path → product opportunity → experience loop → success metrics → validation plan/resources → decision required.

Avoid leading with a feature inventory.

## Business review

Use when explaining performance and agreeing on corrections.

Suggested arc: conclusion → target vs. result → process breakdown → what worked → root causes → corrective actions → risks/trigger points → owners and decisions.

Do not present correlation as cause. Put data definitions next to the metric or in notes.

## Sales proposal

Use when moving a customer toward evaluation, pilot, or purchase.

Suggested arc: customer goal → current cost → shared success criteria → solution → why it fits → implementation → value/investment → low-friction next step.

Use customer language before company language. Do not promise unsupported ROI.

## Fundraising

Use when seeking a follow-up meeting or diligence.

Suggested arc: one-line value → painful problem → distinct solution → reachable market → business model → traction → team/advantage → round plan and milestones.

Every market and traction number needs a source and date.

## Teaching

Use when the audience must understand and transfer a skill.

Suggested arc: observable learning goal → activating problem → core concept → mechanism → worked example → common mistake → practice → application/next exercise.

Exams or quizzes are checks after teaching, not substitutes for teaching.

## General professional report

When no specialized scenario fits, use: context → stakes → evidence → implications → recommendation → action.

## Mode adjustments

- **Quick**: use fewer slides and one evidence placeholder list at the end.
- **Professional**: show decision criteria, alternatives, risks, and ownership.
- **Creative**: vary composition and pacing, but keep the same factual discipline and decision path.
